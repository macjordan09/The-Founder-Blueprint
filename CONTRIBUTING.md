# CONTRIBUTING

Purpose
- Set clear standards and processes for contributions (human or AI) to The-Founder-Blueprint repository.

Scope
- Applies to all contributors: maintainers, external collaborators, contractors, and automated agents (bots/Copilot).

Core principles
- Every contribution must improve how we think, decide, research, or execute.
- Follow the repository Writing Standards: professional, timeless, evidence-based, structured, explain reasoning, identify assumptions, include risks, define success criteria, recommend next actions.
- Prefer edits via pull requests. Keep direct pushes to the default branch reserved for urgent fixes by maintainers.

How to contribute
1. Issue first: Open an issue describing the problem, context, proposed change, assumptions, risks, and success criteria.
2. Draft: Create a branch named `feat/<short-description>` or `doc/<short-description>` from the default branch.
3. Commit: Use atomic commits with messages that start with a type: `feat:`, `fix:`, `docs:`, `chore:`, `perf:` followed by a concise description and a short rationale.
4. PR: Open a pull request linking the issue, with a clear summary, decision checklist, and testing or validation steps.
5. Review: At least one independent reviewer must approve PRs that change strategy, governance, or research outputs. For editorial changes, prefer review by a second editor.
6. Merge: Use the repository’s default merge method. Maintain a clean linear history for strategic documents (squash when appropriate).

Standards for content
- Documents must include Purpose, Context, Problem, Analysis, Recommendations, Decision (if made), Risks, Next Steps, References where relevant.
- Cite primary sources where possible. Use links to datasets and documents.
- Explicitly state assumptions, trade-offs, and unresolved questions.

Automation & bots
- Automated commits must include a clear rationale and reference an issue or PR.
- Copilot/assistant acting in the repo must follow COPILOT_INSTRUCTIONS.md and obtain explicit owner approval for governance changes.

Editorial & legal
- Add a CODE_OF_CONDUCT.md and licensing file if not present. Major legal changes require owner approval.

Onboarding new contributors
- New contributors should be pointed to COPILOT_INSTRUCTIONS.md, this CONTRIBUTING.md, and DECISION_FRAMEWORK.md.

Contact & escalation
- For disputes or unclear decisions, escalate to repository owner (macjordan09) or create an internal governance issue tagged `governance`.
